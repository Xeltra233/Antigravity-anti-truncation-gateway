<a name="中文说明"></a>
## 🇨🇳 中文说明

高性能、无 UI、环境变量优先配置的 OpenAI Chat Completions 协议防截断兼容网关，专为解决大模型在重度提示词（如 SillyTavern 复杂预设/角色卡、Prompt Pre-fill）环境下回答截断、格式丢失与工具冲突问题而设计。

### 🌟 核心特性

1. **防截断合成传输协议**：
   - 动态为每个请求生成高熵（96-bit 随机 Nonce）的请求级唯一合成传输工具（如 `agw_emit_7f3a91c8d42e6b1a9c02a547`）。
   - 指示模型将最终可见回答放入该工具的参数中输出，有效利用 Function Call 机制绕过常见截断与前缀限制。
   - 网关接收响应后精准解构，还原为标准 `assistant.content`，对外完全透明。
2. **原生模型 ID 零映射透传**：
   - 客户端传入的模型 ID（如 `gemini-3.5-flash-low`, `claude-sonnet-4-6`）原样逐字转发给上游，不建立别名，不污染 ID。
3. **真实工具原样保真**：
   - 下游客户端定义的真实 Tools（如天气、搜索、代码执行、Cherry Studio 工具）原样保留，模型生成的真实工具调用不被吞噬或篡改。
4. **空 Assistant Content 强约束与绝对防拼接**：
   - 保证合成回答与普通回答绝不发生字符串拼接，彻底杜绝双来源语言衔接错误。
5. **极速增量流式（SSE）状态机**：
   - 逐字节增量解析 UTF-8 与 JSON 转义序列，已验证稳定字符即时 flush，首字几乎零附加延迟。
6. **确定性有界格式修复与空回自动重试**：
   - 针对模型可能产生的代码围栏、未闭合引号、尾逗号提供确定性本地修复。
   - 上游发生空回（完全没有任何回复）时，自动触发重试（默认 3 次）。
7. **文本模型智能正则识别与非文本模型原生透传**：
   - 内置智能正则分类，仅对文本/Chat 对话模型启用防截断包装；非文本模型（如 image/vision-only、audio、tts、whisper、embedding 等）完全原封不动透传。
8. **支持 Assistant 预填（Prompt Pre-fill）自适应**：
   - 针对酒馆总结插件等在请求末尾包含 `assistant` 轮次的场景，自适应在末尾以 `user` 轮次闭环，彻底解决 Gemini/CPA 上游 400 报错。
9. **极简配置与高并发无锁热路径**：
   - 支持通过 `API_KEY` 环境变量直接配置单一测试 Key，也支持可选的多 Key 与无 UI 管理 API。
   - 鉴权热路径完全基于不可变内存快照与 HMAC-SHA256，零 SQLite/Mutex 争用。

### 🚀 快速开始

#### 1. 编译与极简运行 (推荐)
要求环境：Go 1.24+

```bash
# 编译
go build -o gateway ./cmd/gateway

# 运行 (只需指定上游地址、上游密钥、以及你希望给下游用的 API_KEY)
export UPSTREAM_BASE_URL="https://your-upstream-url.com" # 只需填写根链接
export UPSTREAM_API_KEY="sk-your-upstream-key"
export API_KEY="sk-antigravity-123456" # 下游客户端连接网关时使用的 Key

./gateway
```

#### 2. Windows 批处理快速启动 (`run.bat`)
```bat
@echo off
set UPSTREAM_BASE_URL=https://your-upstream-url.com
set UPSTREAM_API_KEY=sk-your-upstream-key
set API_KEY=sk-antigravity-123456
set PORT=8080

gateway.exe
```

### ⚙️ 环境变量说明

| 环境变量 | 必需 | 默认值 | 说明 |
| :--- | :---: | :--- | :--- |
| `UPSTREAM_BASE_URL` | **是** | - | 上游 API 根链接（如 `https://api.openai.com`，无需写 `/v1`） |
| `UPSTREAM_API_KEY` | 视模式 | - | 上游 Bearer API Key |
| `API_KEY` | 否 | - | 下游客户端通用 API Key（最简单 Key 配置） |
| `UPSTREAM_EMPTY_RETRIES`| 否 | `3` | 上游空回（完全无回复）时的自动重试次数 |
| `WRAPPER_MODE` | 否 | `prefer` | 包装模式：`prefer`（推荐）、`required`、`off`（透传回滚） |
| `RECOVERY_POLICY` | 否 | `repair` | 格式恢复策略：`repair`、`repair_then_retry`、`fail` |
| `CONTROL_MESSAGE_POSITION`| 否 | `tail` | 注入位置：`tail`（末尾强生效）、`head`、`system_tail` |
| `PORT` | 否 | `8080` | 服务监听端口 |
| `HOST` | 否 | `0.0.0.0` | 服务监听地址 |
| `ADMIN_API_KEY` | 否 | `admin-secret-key-12345` | 多 Key 动态管理接口 Bearer Key（可选） |
| `KEY_HMAC_SECRET` | 否 | 默认内置 | 下游 Key 摘要签名密钥（可选） |

### 📱 客户端接入 (如 SillyTavern / Cherry Studio / NextChat)

- **API 基础 URL (Base URL)**: `http://127.0.0.1:8080/v1`
- **API Key**: `API_KEY` 中配置的值（如 `sk-antigravity-123456`）
- **模型**: 直接输入或选择上游原生模型名称（如 `gemini-3.5-flash-low`, `gemini-3.7-flash-high`）

#### cURL 请求示例
```bash
curl http://localhost:8080/v1/chat/completions \
  -H "Authorization: Bearer sk-antigravity-123456" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gemini-3.5-flash-low",
    "messages": [
      {"role": "user", "content": "Hello!"}
    ]
  }'
```

## 🇬🇧 English Documentation

High-performance, headless, environment-variable-configured anti-truncation compatibility gateway for OpenAI Chat Completions. Designed specifically to prevent large language models from truncation, format breakdown, and tool collisions in heavy-prompt environments (e.g. SillyTavern complex presets, character cards, prompt pre-fill, and tool-use clients).

### 🌟 Key Features

1. **Anti-Truncation Synthetic Transport Protocol**:
   - Generates a high-entropy (96-bit random nonce) request-scoped synthetic transport tool (e.g. `agw_emit_7f3a91c8d42e6b1a9c02a547`) per request.
   - Instructs models to output the user-visible answer inside this function parameter, completely bypassing common text completion truncation limits.
   - Normalizes the response back to standard `assistant.content` before returning to downstream clients.
2. **Native Model ID Passthrough**:
   - Passes model IDs (e.g., `gemini-3.5-flash-low`, `claude-sonnet-4-6`) verbatim without aliasing or ID alteration.
3. **Genuine Downstream Tool Fidelity**:
   - Preserves downstream tool definitions (e.g., web search, file reader) intact. Genuine tool calls generated by models are cleanly passed through without interference.
4. **Empty Assistant Content & Anti-Concatenation Invariant**:
   - Enforces that synthetic responses are never concatenated with upstream plain `assistant.content`, eliminating dual-source output conflicts.
5. **Low-Latency Streaming (SSE) State Machine**:
   - Incremental rune/surrogate decoding state machine emits stable verified characters immediately with near-zero added latency.
6. **Bounded Format Repair & Automatic Empty Retries**:
   - Built-in deterministic JSON repair for markdown fences, unclosed quotes, brackets, and trailing commas.
   - Automatically retries upstream if it returns an empty response (default 3 times).
7. **Smart Model Filtering**:
   - Applies synthetic protocol to text/chat models while passing non-text models (image, vision, audio, TTS, whisper, embeddings) through verbatim.
8. **Assistant Pre-fill Compatibility**:
   - Automatically adapts prompts ending with an assistant message to end with a user turn, preventing upstream 400 errors (e.g., on Gemini/CPA).
9. **Zero-Lock Hot-Path Auth & Simple Config**:
   - Supports simple single `API_KEY` configuration or dynamic multi-key management with SQLite & immutable atomic memory snapshots.

### 🛡️ Monitoring & Health Probes

- `GET /healthz`: Liveness probe (`200 OK`)
- `GET /readyz`: Readiness probe (`200 OK`)
- `GET /metrics`: Standard Prometheus metrics (request counts, transform latencies, TTFB, active streams)
- `WRAPPER_MODE=off`: Emergency rollback to pure passthrough mode.
